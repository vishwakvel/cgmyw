# P-measure daily series: CRSP via WRDS primary, yfinance adjusted close and WRDS options-file spot as successive fallbacks

Status: accepted (revised 2026-08-07, same day as initial draft; revised again 2026-08-17)

A direct meeting with Dr. Madan on 2026-08-07 clarified that P-measure fitting only requires a daily price/return time series — it does not require options data at all, so WRDS access is not a hard dependency for the P-fit step specifically. He named Yahoo Finance, Google Finance, or any comparable daily close source as acceptable.

This ADR originally resolved that guidance by staying WRDS-only (reusing column 7, no new dependency) and flagged the choice for the user to confirm. The user has now confirmed directly: they want the professor's Yahoo/Google guidance actually used, not just decoupled-in-principle-while-staying-on-WRDS-in-practice. That original resolution is superseded by this revision.

On 2026-08-17, the user relayed further guidance from Dr. Madan, given directly rather than at the 2026-08-07 meeting: when working with daily returns, the data from CRSP in WRDS can be taken to be in the form of daily returns that is inclusive of dividends and corrected for splits. This is materially more specific than the "Yahoo Finance, Google Finance, or any comparable daily close source" wording the 2026-08-07 revision above was built on — the professor named a specific database that the user already has access to. Presented with the choice directly, the user selected CRSP-via-WRDS over both yfinance's raw close and its adjusted close. The 2026-08-07 yfinance-primary resolution above is superseded by this second revision.

**Decision**: The P-fit's daily return series resolves across three tiers, in priority order.

1. **Primary** — the CRSP daily stock file exported from WRDS's newer CIZ-format query (not the legacy `dsf` field names), read from a user-produced CSV at `WRDSdata/aapl_crsp_returns.csv`. The user's actual export covers AAPL 2020-01-02 to 2025-12-31 (wider than the options-data window on purpose — extra trailing history only helps the rolling 252-day P-fit window, no downside), verified header `PERMNO,HdrCUSIP,Ticker,PERMCO,DlyCalDt,DlyPrc,DlyRet,DlyRetMissFlg` (1508 rows, single PERMNO 14593, zero missing-flag rows). CRSP's `DlyRet` is the holding-period return, already dividend-inclusive and split-corrected by CRSP convention; `DlyRetX` excludes dividends and is the wrong field. Daily log return is `ln(1 + DlyRet)`, computed directly from `DlyRet` — returns are never reconstructed from `DlyPrc` alone, which is not dividend-adjusted on its own.
2. **Fallback and cross-check** — `yfinance`'s dividend/split-adjusted close (`auto_adjust=True`), used when the CRSP file is absent, fails to parse, or yields too short a series, and cross-checked against CRSP on overlapping dates whenever both are available.
3. **Second fallback and further cross-check** — the WRDS options-file spot column (the existing `daily_close_series`, `COL["spot"]`), used when neither of the above is available, and cross-checked against whichever of the first two succeeded.

Cross-source disagreement, on any pair, logs a warning and never blocks the fit — the same soft sanity-check posture as the first revision. WRDS's own spot column, or yfinance's adjusted close, may legitimately differ slightly from CRSP's `RET`-derived return on dividend/split-adjustment or intraday-timing conventions.

The professor named CRSP specifically this time, not the generic "Yahoo Finance, Google Finance, or any comparable daily close source" wording the 2026-08-07 revision was built on. The user has a WRDS license and chose to use it for this purpose. And `RET` is the standard, auditable, dividend- and split-correct convention for daily returns in academic finance work — more defensible than an adjusted-close series reconstructed by a free API whose adjustment methodology is undocumented and can change without notice.

This reopens the project's "no live data fetching" constraint, narrowed rather than dropped: it now applies only to Q-measure/options data, which stays WRDS-only (unaffected, still deferred to Phase 1.5). The P-measure time series remains the exception — sourced primarily from WRDS's own CRSP file rather than a live fetch, with yfinance retained as a live-fetch fallback.

Rejected alternative: keeping WRDS's options-file spot column as primary and yfinance as an optional cross-check only (the original resolution). Rejected because the user was explicit that both sources should be *used* for the P calculation, not just available as a backstop — treating Yahoo/Google as the professor named it, not as a fallback to a fallback.

Also rejected, as of this second revision: yfinance as primary (the 2026-08-07 resolution above). It was the correct reading of "Yahoo or Google is fine" at the time, but that guidance was a statement about what is *acceptable*, not about what is *best available* to a researcher who already holds a WRDS license — and the professor's later, more specific CRSP guidance supersedes it. yfinance is demoted, not removed: it remains the first fallback and an independent cross-check precisely because it is sourced independently of WRDS, so agreement between the two is real evidence rather than a tautology.

Consequence: `data.py` gains a `load_crsp_returns` reader alongside the existing yfinance fetcher and WRDS-derived `daily_close_series`. `daily_close_series_for_pfit` becomes a three-tier resolver whose reported source is one of `crsp`, `yfinance`, or `wrds_fallback`. The yfinance call is corrected to request the dividend/split-adjusted series (`auto_adjust=True`), which it previously did not — an outright bug under the professor's total-return convention, independent of tier ordering. DATA-02, the Phase 1 ROADMAP success criterion, `01-CONTEXT.md`'s D-12, plans 01-01 and 01-03, `.planning/PROJECT.md`, and `.claude/CLAUDE.md` are all updated to match. `WRDSdata/aapl_crsp_returns.csv` does not exist yet: it is a known blocking dependency for exercising the primary path against real data, while synthetic- and injected-data tests of that path can be written and run immediately.
