# Reconstruct complex-argument Kummer U from `scipy.special.hyp1f1`, not `scipy.special.hyperu`

Status: accepted

`.claude/CLAUDE.md`'s original Numerical constraint stated the characteristic exponent "must use `scipy.special.hyperu` (handles complex input) rather than a hand-rolled series." That premise is factually false and was disproved by direct execution during Phase 1 research (01-RESEARCH.md, Pitfall 1): `scipy.special.hyperu` is a real-argument-only ufunc. Its own docstring documents `a, b: Real-valued parameters` and `x: Real-valued argument`, and passing a complex `z` raises `TypeError: ufunc 'hyperu' not supported for the input types...`. ψ(u) requires U(Wn, Wn+Yn, G+iu) and U(Wp, Wp+Yp, M-iu) — complex arguments by construction, evaluated at every point of an FFT/tail-integration grid. Following the literal constraint text makes MODEL-01 unimplementable, not merely suboptimal.

The *goal* the constraint protects — a correct ψ(u) built on scipy special functions, not a hand-rolled hypergeometric series solver — is fully preserved. `src/cgmyw/model.py::kummer_u` reconstructs U(a,b,z) from two scipy primitives, `scipy.special.hyp1f1` (which does support complex `z`, on scipy ≥1.14 — see below) and `scipy.special.gamma`, dispatched by `|z|`:

- **Small `|z|` (below `KUMMER_Z_THRESHOLD = 20.0`):** the Tricomi relation (DLMF 13.2.42), summing two `hyp1f1`-based terms. Accurate but suffers catastrophic cancellation as `|z|` grows, since both terms individually grow like `e^{Re(z)}` while their difference decays like `z^{-a}`.
- **Large `|z|`:** the DLMF 13.7.3 asymptotic series, pure elementary complex arithmetic (no special-function calls), accurate exactly where Tricomi degrades.

Both branches were validated in research against `mpmath.hyperu` at arbitrary precision (relative error <1e-9 for small `|z|`, <1e-7 for large `|z|`, reconfirmed by `tests/test_model.py`'s parametrized cross-checks on both sides of the threshold), and the reconstruction reduces to the classical CGMY closed form at the symmetric specialization to 3.0e-14 across a 2001-point real-`u` grid spanning `[-300,300]` — six orders of magnitude inside MODEL-01's 1e-8 bar. `scipy.special.hyperu` is still used, where it is valid: as an independent real-`z` cross-check on `kummer_u` in the test suite (`test_kummer_u_agrees_with_scipy_hyperu_real_z`).

**Version floor:** `scipy>=1.14` is a hard requirement, not a preference — `hyp1f1`'s complex-argument support was broken prior to that release (scipy GitHub issue #20797, fixed by PR #20805) and silently returned wrong real-only values for complex `z` in scipy 1.10–1.13.1. Pinned in `pyproject.toml` with a comment naming the issue.

**Known, deliberately unmitigated singularity:** the Tricomi relation has a genuine mathematical pole when `b = W+Y` lands on a positive integer — `gamma(1-b)` and `gamma(b-1)` both blow up there simultaneously (confirmed directly: `b=1.0` exactly produces `nan+nanj`, `b=1.02` a few hundredths off is finite and well-behaved). This is not a defect in the reconstruction; it is inherent to the Tricomi connection formula itself (a genuinely different closed form, involving `log(z)` and digamma functions, is required exactly at integer `b` — out of scope for this phase, since the P-fit's continuous optimizer treats it as a measure-zero event). `model.py` deliberately does **not** trap this NaN: the P-fit's objective function (plan 01-02) owns rejecting a non-finite `ψ` result so L-BFGS-B steps away cleanly, per the plan's own instruction not to swallow the signal this low in the stack. One consequence worth recording here: 01-01-PLAN.md's own acceptance-criteria shell examples for the complex-`u` and vanishing-at-origin checks used `Wn=0.4, Yn=0.6` (summing to exactly `b=1.0`), accidentally landing on this exact documented pole — `tests/test_model.py` instead verifies the same behavior with `Wn=0.42` (`b=1.02`), a few hundredths off the singularity, which is finite and passes.

This follows the project's own ADR-0002 precedence rule (source truth over paraphrase — the underlying requirement, a correct ψ(u), is what is honored) and CLAUDE.md's own directive to write correct code. `.claude/CLAUDE.md`'s Numerical constraint bullet is updated alongside this ADR to describe the actual mechanism and point here, so a future agent does not reintroduce the impossible literal call.

Consequence: every complex-argument evaluation of U in this project — the FFT-grid terms and the two real-argument "constant" terms in `psi_cgmyw` alike — routes through the single `kummer_u` wrapper, never `scipy.special.hyperu` directly on a complex value. Phase 1.5's Carr-Madan pricer, which evaluates ψ at the damped complex argument `u = v - (alpha+1)j`, depends on this reconstruction being correct; the `alpha < M-1` integrability condition maps directly onto `kummer_u`'s principal-branch validity condition `Re(zg) > 0, Re(zm) > 0` noted in `psi_cgmyw`'s docstring.
